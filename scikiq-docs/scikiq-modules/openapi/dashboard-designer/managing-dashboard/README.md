# Managing Dashboard

***

### Instructions for Using this Page

* Click on an image to view it in a larger and clearer format.
* The inputs shown in the images are for example purposes only. You must enter the correct and actual data.

***

### Overview

Once a dashboard is created, it is displayed on the **Dashboard Lists** page, which serves as a centralized location for dashboard management. From this page, you can perform various actions such as updating dashboard configurations, viewing change history, using the rediscover option to refresh dataset changes, creating assets, managing resource permissions, and deleting dashboards that are no longer required. This page provides a convenient way to maintain, monitor, and manage dashboard-related activities from a single location. &#x20;

***

### Managing Dashboard

Depending on your requirements, you can perform the following tasks on a dashboard:

{% tabs %}
{% tab title="View Dashboard" %}
**Overview**

The **View Dashboard** feature allows users to access and interact with a dashboard after it has been created and published. It provides a consolidated view of charts, widgets, tables, and other visual components configured within the dashboard. Users can analyze data, apply filters, interact with visualizations, and gain insights based on the displayed information. This feature helps users monitor key metrics and make informed decisions through an interactive and user-friendly interface. &#x20;

***

**Procedure**

The below step-by-step instructions help you understand how to view dashboard:

1. On the **SCIKIQ left navigation bar,** click **Dashboard List** under **SCIKIQ CONSUME**.

2. On the **Dashboard List page**, click the **View** icon corresponding to the required dashboard.

The dashboard is displayed. See the below example image.

{% tab title="View Change History" %}
**Overview**

The **View Change History** feature allows users to track and review modifications made to a dashboard after its creation. It provides visibility into changes such as updates to configurations, widgets, layouts, filters, and other dashboard settings. This feature helps maintain an audit trail, making it easier to identify what changes were made and when they occurred. It also supports better monitoring, troubleshooting, and version tracking of dashboard updates. &#x20;

***

**Procedure**

The below step-by-step instructions help you understand how to view change history:

1. On the **Dashboard List page**, click the **Update** icon corresponding to the required dashboard.

<img src="../../../../.gitbook/assets/unknown (246).png" alt="Dashboard List - Change History Icon" width="563">

The change history is displayed. See the below image.

2. On the **Change History** page:

* Use the **Filters** or **Quick Select** options to view the change history of a required dashboard.
* Click on a **row** to view the modification details.

The modification details are displayed. See the below image.

{% tab title="Rediscovery" %}
**Overview**

The **Rediscover** feature allows users to refresh and synchronize the dashboard with the latest changes made to the underlying dataset or data source. It helps identify newly added fields, updated configurations, or structural changes in the dataset and reflects them within the dashboard. This feature ensures that the dashboard remains aligned with the most recent data definitions and prevents inconsistencies caused by outdated metadata. Rediscover helps maintain data accuracy and keeps dashboard components up to date. &#x20;

***

**Procedure**

The below step-by-step instructions help you understand how to rediscover dashboard:

1. On the **Dashboard List page**, click the **Rediscover** icon corresponding to the required dashboard.

<img src="../../../../.gitbook/assets/unknown (248).png" alt="Dashboard List - Rediscover Icon" height="288" width="624">

The dashboard is rediscovered.
{% endtab %}

{% tab title="Create Asset" %}
**Overview**

The **Create Asset** feature allows users to generate reusable assets from an existing dashboard for easier access and management. These assets can be utilized across different modules or shared with other users based on business requirements. This feature helps improve reusability, reduce duplication of effort, and maintain consistency across reports and dashboards. It also enables efficient organization and management of dashboard-related resources. &#x20;

***

**Procedure**

The below step-by-step instructions help you understand how to create assets:

1. On the **Dashboard List page**, click the **Create Asset** icon corresponding to the required dashboard.

<img src="../../../../.gitbook/assets/unknown (249).png" alt="Dashboard - Create Asset Icon" height="288" width="624">

The Add Asset dialogue box is displayed.

2. On the **Add Asset** dialogue box, enter the required details, and then click the **Next** button.

<img src="../../../../.gitbook/assets/unknown (250).png" alt="Dashboard List - Add Asset Dialogue Box" height="271" width="624">

3. On the next page, enter the **Asset** description, and then click the **Submit** button.

The asset is created.
{% endtab %}

**Procedure**

{% tab title="Delete Dashboard" %}
**Overview**

The **Delete Dashboard** feature allows removing dashboards that are no longer required or relevant. This helps maintain a clean and organized dashboard repository by eliminating outdated or unused dashboards. Removing unnecessary dashboards also reduces clutter and improves overall system management. It is important to verify the dashboard details before deletion to avoid accidental removal of important data or configurations.

***

**Procedure**

The below step-by-step instructions help you understand how to delete a dashboard:

1. On the **Dashboard List page**, click the **Delete** icon corresponding to the required dashboard.

<img src="../../../../.gitbook/assets/unknown (253).png" alt="Dashboard List - Delete Icon" height="288" width="624">

The Delete Notification is displayed.

2. On the **Delete Notification**, click the **Yes** button.

The dashboard is deleted.
{% endtab %}

{% tab title="View Asset" %}
**Overview**

The **View Assets** feature allows users to access and view assets that have been created from dashboards or related resources. It provides a centralized location to manage and review available assets for reuse across different modules or applications. This feature helps improve resource organization, enhances accessibility, and reduces duplication by allowing users to leverage existing assets. {% tab title="View or Hide a Column" %}
**Overview**

The **View or Hide a Column** feature allows controlling the visibility of columns within a table based on their requirements. It enables displaying only the relevant columns and hide unnecessary information, resulting in a cleaner and more focused view of the data. This feature improves readability and enhances the user experience by reducing visual clutter. It also provides flexibility in customizing the table display according to specific business or reporting needs.

***

**Procedure**

> <mark style="color:red;">**Note:**</mark> On the **Dashboard List** page, the column headers displayed in **blue** indicate **visible** columns, whereas the tabs displayed in **grey** represent **hidden** columns.

The below step-by-step instructions help you understand how to view or hide a column:

1. On the **Dashboard List** page, if you want to hide a column, click on that column header.&#x20;
2. If you want to view it, click again on the column header.

<img src="../../../../.gitbook/assets/unknown (269).png" alt="Dashboard List - Visible and Hidden Columns" height="249" width="624">
{% endtab %}

{% tab title="Switch Version" %}
**Overview**

The **Switch Version** feature allows navigating between different versions of a dashboard and view previously saved configurations or updates. It helps track changes made over time and provides the flexibility to access earlier versions when required. This feature supports version management by enabling users to compare modifications and maintain consistency across dashboard updates. It also helps reduce the risk of losing important configurations by preserving historical versions.

***

**Procedure**

The below step-by-step instructions help you understand how to switch versions:

1. On the **Dashboard List** page, select the required **version** from the Version drop-down box corresponding to the required dashboard.

![Dashboard List - Version Drop-Down Box](<../../../../.gitbook/assets/unknown (279).png>)

The Version Change Confirmation message box is displayed.

2. On the **Version Change Confirmation** message box, click the **Yes** button.

![Dashboard List - Version Change Confirmation Message Box](<../../../../.gitbook/assets/unknown (280).png>)
{% endtab %}
{% endtabs %}

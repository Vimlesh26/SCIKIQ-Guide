### **2. Pie Chart**

A **Pie Chart** is a circular graphic used to represent data as proportional slices. Each slice corresponds to a category’s share of a whole, making it ideal for showing percentage or proportional data in a visually intuitive format.

#### **When and Why to Use a Pie Chart**

Pie charts are best used when:

* You want to **compare parts of a whole**.
* There are **limited categories** (ideally fewer than 6–8).
* The differences between values are **distinct enough to visualize**.
* You need a **quick visual impact** for presentations or dashboards.

They are not ideal for comparing values of similar size or when there are many small segments, as it may lead to clutter and misinterpretation.

#### **Design Characteristics**

* The chart is shaped like a **circle** divided into **slices**.
* Each slice represents a **category's share** of the total value.
* The **size of the slice** is determined by the proportion of the category to the total sum.

#### **Chart Configuration**

* **Dimension (Category)**: This defines what the slices represent (e.g., company names).
* **Metric (Value)**: This defines the numerical value determining the size of each slice (e.g., total revenue per company).

For example:

* **Dimension**: Company Name
* **Metric**: Sum of Revenue

#### **Purpose of the Pie Chart**

The primary purpose is to show how a **whole is divided among various categories**. It gives a clear picture of:

* Which categories are most significant.
* The relative contribution of each category.
* Visualizing percentage-based comparisons at a glance.

### Vertical Bar Chart

A Vertical Bar Chart is a standard visualization used to represent and compare quantitative values across different categories. In this chart, bars are drawn vertically for each category, and different metrics can be represented side-by-side for easy comparison.

#### When and Why to Use a Vertical Bar Chart

Use this chart when:\
\- You want to compare values across categories (e.g., different verticals or departments).\
\- You need to visualize actual vs. budgeted performance side-by-side.\
\- The goal is to highlight performance gaps or over/under achievements.\
\- Categories are discrete and well-labeled (not continuous).

This format is effective for business reviews, dashboards, or reports focused on financial performance across multiple groups.

#### Design Characteristics

\- Each category (vertical) is represented along the X-axis.\
\- The Y-axis represents the magnitude of the metric (e.g., revenue, cost, margin).\
\- Bars are grouped by category and aligned vertically.\
\- Multiple metrics (e.g., Actual and Budget) can be displayed using clustered bars or different bar styles for comparison.

#### Chart Configuration

\- Dimension (Category): This defines what the X-axis represents, such as Project Name or Vertical Name.\
\- Metrics (Values): These define the heights of the bars. Example metrics could include:\
&#x20; • Revenue\
&#x20; • Cost\
&#x20; • Gross Margin

### 3. Horizontal Bar Chart

A Horizontal Bar Chart is a common visualization technique where bars extend horizontally from the Y-axis. Each bar represents a category, and its length corresponds to the value of a metric. This chart type is especially useful when category labels are long or when you want to compare values across categories clearly.

#### **When and Why to Use a Horizontal Bar Chart**

Use this chart when:

* You need to compare quantitative values across categories with long or descriptive labels.
* The number of categories is large, and vertical space is limited.
* You want to highlight differences in data clearly and make reading category names easier.
* You want to display rankings or ordered data effectively.

#### **Design Characteristics**

* **Y-axis**: Displays categories or dimension labels (e.g., project names, company names).
* **X-axis**: Represents metric values (e.g., revenue, cost).
* Bars extend horizontally from the Y-axis.
* Bars are aligned vertically along the category axis, making category labels easier to read.

#### **Chart Configuration**

* **Dimension (Category)**: Defines the categories shown on the Y-axis (e.g., `Project_name`, `Company_name`).
* **Metric (Value)**: Defines the length of the bars along the X-axis (e.g., `Revenue`, `Cost`, `Profit`).

### 4. Vertical Stacked Bar Chart

A Vertical Stacked Bar Chart is used to represent multiple data series stacked one on top of the other within single bars. This allows for a clear comparison of total values across categories while simultaneously breaking down the contribution of each sub-category or metric.

Each vertical bar represents a category (e.g., Project Name) and consists of segments showing the proportion of each metric (e.g., Gross Margin, Revenue). The height of the entire bar shows the total value, while the segments help analyze the composition.

#### **When and Why to Use a Vertical Stacked Bar Chart**

Use this chart when:

* You want to show both the **total value** and the **composition** of metrics for each category.
* You want to compare **metrics across projects**, such as how gross margin and revenue contribute to the overall financial figures.
* Space is limited and you want to avoid multiple side-by-side bars.
* You want to emphasize part-to-whole relationships in your data.

#### **Design Characteristics**

* **X-axis**: Displays categories (e.g., Project Names).
* **Y-axis**: Represents metric values (e.g.,Actual Amount).
* **Bars**: Each bar is a stack composed of multiple metrics (e.g., revenue stacked with gross margin).
* **Color Coding**: Each segment in the stack has a distinct color to identify the metric it represents.
* **Stacking Logic**: Metrics are stacked vertically within the same bar for each category.

#### **Chart Configuration**

* **Dimension (Category)**:
  * `Project_name` — This defines the X-axis and represents each unique project.
* **Metrics (Stacked Segments)**:
  * `Project_Revenue`
  * `Project_Gross_Margin`

Each of these metrics will appear as a separate colored segment within the vertical bar for every project.

<figure><img src="../../.gitbook/assets/image (426).png" alt=""><figcaption></figcaption></figure>

**Purpose**

This chart is used to:

* Show the overall value (e.g., revenue) of each project while highlighting the contribution of gross margin within that total.
* Compare projects based on their total financial output and composition.
* Support analysis of profitability and performance structure per project.

{% hint style="warning" %}
**Note:**\
The **styling and formatting options** for **Vertical Stacked Bar Charts** and **Horizontal Stacked Bar Charts** are **exactly the same** Just like the **Vertical Bar Chart**. The only difference is in orientation:

* In a **Vertical Stacked Bar Chart**, categories are shown on the X-axis, and values stack upward along the Y-axis.
* In a **Horizontal Stacked Bar Chart**, categories are on the Y-axis, and values stack horizontally along the X-axis.

All configuration options such as titles, axes, labels, data formatting, legends, tooltips, and color settings remain consistent across both chart types.
{% endhint %}

### 6. Line Chart

A Line Chart is a fundamental visualization used to display data points connected by straight lines, showing trends over a continuous dimension, typically time. It effectively illustrates how one or more metrics change across intervals or categories, making it ideal for trend analysis and forecasting.

#### **When and Why to Use a Line Chart**

Use this chart when:

* You want to show trends or patterns over time or ordered categories (e.g., days, months, years).
* You need to compare multiple series and observe their behaviors simultaneously.
* Highlighting rises, falls, cycles, or volatility in data is important.
* Showing continuous data progression is necessary.
*

    #### Dimension (X-Axis)

    * **month**
      * Represents the **time dimension** across which the metrics will be plotted.
      * Data points are plotted sequentially based on the month order.

    Metrics (Y-Axis)

    * **Project\_Revenue**
      * Displays the total revenue generated for the project in a specific month.
    * **Project\_COS** (Cost of Services)
      * Represents the cost associated with delivering the project during that month.
    * **Project\_Gross\_Margin**
      * Shows the margin earned (Revenue - Cost), indicating profitability trends.

### Table(List)

The **Table** chart is a classic tabular layout used in dashboards. It displays data in a structured grid, showing **rows and columns** that make it easy to view and compare multiple records and values simultaneously. This layout offers complete visibility of every data point, making it ideal for precision-based reports.

When to Use

Use the **Table List Chart** when:

* You require **detailed reporting** of data, such as financial statements or audit trails.
* Users need to **view individual records** rather than aggregated or summarized data.
* It's important to **compare multiple fields** across a list of entities.
* You want to **retain the original granularity** of the dataset without grouping or aggregation.

Why to Use

* **Intuitive and familiar format** for most users.
* Supports **complex data analysis** by showing raw metrics alongside computed fields.
* Enables **quick comparison** of values across multiple records.
* Provides **full transparency**, which is critical for compliance and audit-related dashboards.

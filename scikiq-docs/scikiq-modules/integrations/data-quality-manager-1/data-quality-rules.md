# Data Quality Rules

### What is Data Quality

SCIKIQ Data Quality helps businesses easily check and improve the quality of their data. In today’s technology-driven world, reliable data is essential for accurate insights and recommendations. Poor-quality data can harm business decisions and slow down processes. SCIKIQ’s solution allows users to assess data quality using simple, no-code or low-code rules, with built-in or language model-generated rules. These rules are applied to specific data columns, providing an overall score for data quality. With language model-powered data profiling, SCIKIQ suggests areas to improve, while also letting users fine-tune recommendations. This helps ensure data is trustworthy, improving decision-making.

* Ensure data meets the needs of users by following a structured approach.
* Set clear standards for maintaining data quality throughout its lifecycle.
* Track and report on data quality levels regularly.
* Find ways to improve data quality by fixing issues in systems and processes based on user needs.

### **Guiding Principles:**

* **Criticality:** Focus on the most important data for the business, with priority given to data that poses the highest risk if inaccurate.
* **Lifecycle Management:** Manage data quality from creation to disposal, ensuring quality at each step as data moves between systems.
* **Prevention:** Aim to prevent data errors, not just fix them after they happen.
* **Root Cause Fixes:** Address the underlying reasons for data issues, often involving changes to systems and processes.
* **Governance:** Data governance should support data quality, and data quality efforts should help maintain a governed environment.
* **Standards-Driven:** Data quality standards should be clear, measurable, and followed by everyone involved with the data.
* **Business Processes:** Business leaders must ensure their processes produce high-quality data by following set standards.
* **Systematic Enforcement:** System owners must enforce data quality rules.

### Dimensions of Quality

### Accuracy

Accuracy means how well data matches real-world facts or entities. Accuracy is measured by comparing the data to a trusted source that is known to be correct, like a verified system of record or reliable reference data.

### Completeness

Completeness checks if all the necessary data is present. It can be measured at different levels, like the entire data set, individual records, or specific columns. For example, does the data set include all expected records? Are records filled in correctly? Comparing the data set to a trusted source or past data can help assess completeness.

### Consistency

Consistency means that data is represented in the same way within and across data sets. It ensures that data values are aligned and related across different systems or over time. Consistency also refers to data format, making sure that data looks the same throughout. It's important to remember that consistency doesn't always mean the data is accurate or correct—just that it’s consistently formatted and structured.

## Uniqueness

Uniqueness means that each entity appears only once in a data set. Ensuring uniqueness implies that each entity has a specific key value that identifies it and no other entity shares that key. To measure uniqueness, you can test the key structure to confirm each entity is unique.

## Validity

Validity means that data values fit within a defined set of acceptable values. This can be a specific list of valid values, a range or rules that determine what’s valid. The data type, format and level of detail (precision) also matter when defining these rules.

### Creating and Using Data Quality Rules

To effectively manage data quality, follow these steps in creating and using data quality rules:

1. **Define Goals**: Clearly identify what you aim to achieve with data quality, such as accuracy, completeness, or consistency.
2. **Set Quality Criteria**: Develop specific rules that data must adhere to. This includes thresholds, valid ranges, and acceptable formats.
3. **Implement Rules**: Use tools or platforms to apply these rules to your datasets. Ensure integration into your data pipelines or processes.
4. **Monitor Compliance**: Regularly check data against these rules to identify any anomalies or issues.
5. **Adjust as Necessary**: Modify rules as organizational needs or data sources evolve to maintain high quality.

This iterative process ensures data integrity and reliability across your systems.
